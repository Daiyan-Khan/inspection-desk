# InspectionDesk: testing the value of visual AI

I built InspectionDesk to answer a specific applied-AI question: can frozen visual features help a reviewer find more manufacturing anomalies than a deterministic appearance comparator? The success criterion was at least a **10 percentage-point recall improvement without a higher observed false-alarm rate**. I chose a narrow, reproducible candle-inspection task using public images, so the contribution of AI could be measured separately from the interface. This is an engineering portfolio study; customer demand and manufacturing outcomes have not been validated.

The application gives a reviewer an original photograph, an adjustable anomaly map, and three independent decisions: defect, acceptable variation, or uncertain. Analysis runs locally in a browser worker; notes and decisions stay in IndexedDB and can be exported. Ten-image collections, keyboard navigation, zoom, cancellation, download recovery and a manual-review fallback make the experiment usable as a small product. Dataset labels are revealed separately and never become reviewer decisions automatically.

The result was a useful but insufficient improvement. DINOv2 detected **50 of 100 anomalies**, compared with zero for the classical comparator, but raised **7 false alarms instead of 2** on 100 normal images. It still missed half the labelled anomalies. The combined success criterion was therefore **not met**. The project demonstrates better ranking and a measured operating-point tradeoff; it does not demonstrate a reliable factory inspection system. The complete evidence is in the [frozen evaluation report](../public/data/evaluation.json).

| Method | Recall | False alarms | Image AP | Pixel AP | TP / FN / FP / TN |
|---|---:|---:|---:|---:|---:|
| Frozen DINOv2-small | 50% | 7% | 0.871 | 0.115 | 50 / 50 / 7 / 93 |
| Multiscale colour + gradient | 0% | 2% | 0.493 | 0.004 | 0 / 100 / 2 / 98 |
| Raw-pixel reference | 4% | 6% | 0.510 | 0.007 | 4 / 96 / 6 / 94 |

AP means average precision, a ranking measure rather than accuracy at the chosen threshold. TP/FN count detected/missed anomalies; FP/TN count flagged/unflagged normal images. Against the classical comparator, the paired recall improvement was 50 points (95% bootstrap interval: 40–60), while the observed false-alarm increase was 5 points (interval: −1 to 11). Image AP improved by 0.378 (interval: 0.279–0.453). These intervals describe sampling uncertainty; the false-alarm interval crossing zero does not establish equivalence or satisfy the observed-rate criterion.

**Methodology.** [VisA](https://github.com/amazon-science/spot-diff) supplies candle photographs and anomaly masks under CC BY 4.0. The official 200-image test set remained intact. A [duplicate audit](../public/data/duplicate-audit.json) identified one essentially identical training/test scene before inference; excluding the training image left **719 fitting normals, 180 calibration normals and 200 test images**. Missing batch identities and unknown foundation-model pretraining overlap limit claims of independence.

I used [Meta’s pretrained DINOv2-small](https://github.com/facebookresearch/dinov2) as a frozen feature extractor, without fine-tuning. All methods shared 1,024 reference patch locations and exact nearest-reference scoring; the image score was the mean of its five highest eligible patch distances. The classical comparator used standardised multiscale Lab colour and gradient statistics. Each method’s threshold targeted 5% calibration false alarms and was locked before test inference. Canonical 224-pixel images and fixed display scales prevented browser resizing or test examples from silently changing the experiment. The [methodology artifact](../public/artifacts/methodology.json) records these choices. This comparison does not establish superiority over every classical method.

**Engineering beyond the model.** A fitting-image parity check exposed material differences between native CPU and WASM quantised execution. I discarded those artifacts and rebuilt using the same pinned ONNX Runtime Web/WASM provider offline and in-browser, before inspecting test outputs. Immutable versions and checksums identify inputs, weights, banks and reports. Display guards reject stale results; delayed storage hydration cannot overwrite newer edits. Cancellation terminates the worker, and reset blocks competing actions. The [architecture](architecture.md) documents these boundaries.

The [browser validation](../public/data/browser-validation.json) passed nine comparisons—three images across three methods—with zero observed score or patch-distance error. The development laptop has an Intel Core i7-12650H, 16 logical processors and 15.63 GiB of OS-reported physical memory. Verification used Codex's embedded Chromium 153 on Windows; inference used single-threaded WASM. Standalone Chrome and Edge were not separately tested. The three measured warm AI runs took **0.61–0.65 seconds**. The first request in this cached validation run took **1.228 seconds**, which is not a cold-network startup measurement. Peak process memory was not measured; the browser memory result was unavailable. Installed system memory is not a measurement of application memory. These observations do not establish performance across devices. The [validation record](validation.md) separates numerical parity, hosted workflow checks and remaining gaps.

**Failures and limits.** The failure collection includes real misses and false alarms. DINOv2’s pixel AP was only 0.115: maps are coarse 16×16 patch scores, not precise segmentation. Resizing may hide small defects, and unusual appearance does not establish defect cause, severity or acceptability. One category, 100 anomalies and an artificial 50% test anomaly prevalence cannot establish factory reliability. No reviewer-time study, adoption evidence or return on investment was measured.

**What I would do next.** I would first review the misses with a manufacturing reviewer and test whether these suggestions improve decisions or simply add work. Then I would define acceptance costs, collect a separate camera-and-batch holdout, and compare higher-resolution features with stronger classical alternatives under a newly frozen protocol. Before broader deployment, I would measure uncached downloads, peak memory and slower devices. Any revised method would need fresh evaluation rather than threshold adjustments justified by this test set.
